Method

Two readers, one score

Only about 2 in every 100 complaints end with the company paying money. A compliance team with a 15-day deadline can't read them all with equal care — so TriageIQ estimates which ones will cost money, and sends those to a senior analyst first.

01 — THE WORDS

A language model reads the complaint

DistilBERT, fine-tuned on how past complaints actually ended. It reads up to about 410 words — enough for 9 in 10 complaints in full.

02 — THE TRACK RECORD

A database recalls the company's history

19 numbers computed in SQL from 4.8 million complaints: how often this company paid on this kind of problem, as known on the day the complaint arrived — never later.

03 — THE CALL

One score, one route

Both are combined into one probability, re-tuned on the newest data. The riskiest 10% go to a senior analyst; the rest get a template reply.

How well it works

Tested on 150,000 complaints from 2024 it never saw

0.82

Inside one company, it ranks a complaint that paid above one that didn't about 82 times in 100 (range 0.815–0.830). The honest test: a bank only sorts its own queue.

92.6%

of all 3,471 payouts sit in the riskiest 10% — what seniors would read.

+1.9

points from adding the track record to the language model (0.804 → 0.822) — the database earns its place.

Honest limits

  • Track records are frozen at the end of 2024.
  • The label is company cost (money paid), not how badly the consumer was harmed.

Under the hood

Data
4.8M real CFPB complaints (2022–24) in PostgreSQL; 1.6M with the consumer's own words
Features
Point-in-time window functions in SQL, leak-tested; the live service reads the same formulas
Model
DistilBERT + a small network over the SQL features, trained on a free Kaggle T4 GPU
Serving
ONNX Runtime on CPU · FastAPI · Docker Compose · NGINX · AWS EC2
This site
Plain HTML, CSS and JavaScript on Vercel, forwarding to the API
